# OpenFunds: передача единой версии Devnet

Работа ведётся в `~/projects/openfunds-full`, ветка `feature/full-openfunds`. На сайте несколько связанных страниц: главная, каталог, создание, проект с историей/чатом, кабинет и профиль. Данные проектов, взносов, сообщений и возвратов хранятся в Solana Devnet и доступны на разных устройствах. Кошельки переключаются через Phantom; сайт запоминает только публичные адреса.

**Программа обновлена и активирована в Solana Devnet 2 октября 2026 года (UTC).** Создание проекта V2, два взноса по 0.01 SOL, сообщение, закрытие и точный возврат 0.02 SOL проверены реальными транзакциями; все подтверждены окончательно. Существующая кампания с 3 SOL и её хранилище сохранили данные и балансы. Локальный интерфейс работает с обновлённой программой. Новый интерфейс на Vercel появится после самостоятельного commit/push владельца и успешной публикации. Агент commit и push не выполнял. Размещение оплатил ранее созданный служебный Devnet-кошелёк; для проверки использованы одноразовые подписанты в памяти, личные кошельки не требовались.

## Повторить локальную проверку

Используется установленный Anchor 1.2.0 / Agave 3.1.10 и уже имеющиеся инструменты/зависимости. Новые версии не устанавливаются. Для этого валидатора сборка должна иметь архитектуру **SBF v0**; стандартная архитектура Anchor v3 давала `Program is not deployed / Unsupported program id` при существующем executable аккаунте.

```sh
cd ~/projects/openfunds-full/solana/anchor
anchor build --no-idl --ignore-keys --arch v0 -- --offline --skip-tools-install
anchor idl build -o target/idl/openfunds.json -- --offline
../node_modules/.bin/tsx --test tests/openfunds.test.ts
```

IDL создаётся отдельно: параметры сборки SBF нельзя передавать в его `cargo test`. `--ignore-keys` исключает проверку файла program-keypair CLI. В тестах не читаются существующие файлы кошельков. Валидатор получает отдельный временный ledger и одноразовые подписанты; после проверки этот валидатор останавливается.

Результат последнего полного запуска: **19 тестов, 19 успешных, 0 ошибок, 0 пропусков**. Проверены создание/изоляция проектов, точные повторные взносы, ошибки PDA/сумм/переполнения, общий чат, полномочия, закрытие, возвраты V1/V2, защита от повторного возврата, комиссии/хранение и прямые переводы в Vault. Подробности: `LOCAL_TESTING.md`.

## Что потребуется владельцу для запуска на Devnet

1. Проверить текущую upgrade authority программы и убедиться, что её подпись доступна владельцу. Это публичная проверка:

   ```sh
   solana program show --url devnet Hcy7KiWQE1VfWE8LieGUSq8yAeL1AZEMqjKhDjomc7Fe
   ```

2. Отдельно разрешить обновление программы и оплатить его тестовыми SOL. Ни Phantom-подключение пользователя, ни push сайта не дают права обновления программы. Владелец использует свой настроенный способ подписи; приватные ключи/seed-фразы не передаются в чат и не добавляются в репозиторий.

   Пример команды **для владельца после отдельного согласования**, не выполнявшийся агентом. Обозначения `YOUR_UPGRADE_AUTHORITY_SIGNER` и `YOUR_FEE_PAYER_SIGNER` нужно заменить способом подписи, который владелец контролирует:

   ```sh
   cd ~/projects/openfunds-full/solana/anchor
   solana program deploy --url devnet \
     --program-id Hcy7KiWQE1VfWE8LieGUSq8yAeL1AZEMqjKhDjomc7Fe \
     --upgrade-authority YOUR_UPGRADE_AUTHORITY_SIGNER \
     --fee-payer YOUR_FEE_PAYER_SIGNER \
     target/deploy/openfunds.so
   ```

   Здесь указан существующий публичный program ID для обновления. Если upgrade authority отсутствует либо её подпись недоступна, нужно решение владельца; публикация под другим адресом сама по себе не перенесёт существующие кампании.

3. Опубликовать согласованный интерфейс на Vercel с настройками Devnet. На сайте открыть служебную страницу `/setup`; она не включена в обычное меню. Для текущего домена это `https://openfunds-eight.vercel.app/setup`, **после публикации новой версии интерфейса**.

4. Подключить тестовый Phantom и явно нажать «Активировать после обновления программы». Это инструкция `initialize_platform_v2`: она создаёт единую запись версии 2. После обновления её может оплатить обычный тестовый аккаунт; для этой операции не нужен ключ upgrade authority. Активация не переводит взносы и не закрывает проекты. При открытии страницы автоматически ничего не подписывается.

5. Дождаться подтверждения и надписи «Платформа активирована». Если подпись отправлена, но её подтверждение временно недоступно, `/setup` сохраняет ссылку на транзакцию. Кнопка проверки читает состояние без новой подписи. Повторная отправка заблокирована до проверки; запись активации создаётся один раз.

После активации создать новый проект, открыть его ссылку на втором устройстве, внести небольшую сумму из другого Devnet-аккаунта, проверить историю/чат, затем закрыть проект и проверить возврат. Старые проекты доступны на этих же страницах.

## Что происходит с деньгами

- Взнос через сайт поступает в Vault проекта. Прямой перевод на личный адрес автора не является взносом OpenFunds.
- Закрыть сбор может только автор. Новые взносы и сообщения после закрытия блокируются; история и чат остаются для чтения.
- Возвращается ровно оставшийся **учтённый взнос** каждого спонсора, на его записанный адрес. Повторный возврат запрещён. Спонсор также может получить свой возврат самостоятельно после закрытия.
- Авторский общий возврат выполняется отдельными транзакциями Phantom для каждого спонсора. Отмена/обрыв останавливает обработку; подтверждённые возвраты сохраняются. «Вернуть оставшиеся взносы» продолжает с актуальными остатками. Полное завершение определяется данными цепочки.
- Уже оплаченные комиссии и хранение аккаунтов не входят в сумму взноса. При самостоятельном возврате из старой кампании спонсор дополнительно оплачивает создание записи возврата; его изменение баланса равно взносу минус новая комиссия и это хранение. Когда старый возврат запускает автор, запись оплачивает автор. Для V2 отдельная запись возврата не создаётся.
- Rent хранилища сохраняется. Неучтённый прямой перевод в Vault не увеличивает учтённые взносы и не включается в возврат; после возвратов он остаётся в Vault. Такие переводы не следует использовать для проверки взносов.
- При неизвестном подтверждении сначала проверяется сохранённая транзакция. Сайт не должен повторно отправлять взнос автоматически.

Выдача средств автору, голосование по этапам и Mainnet в этот этап не входят. Закрытие архивирует проект и не удаляет денежную историю.
